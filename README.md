# template-macos-app

A GitHub template for macOS menu bar apps: SwiftUI, Swift 6, Sparkle updates, and a project that builds, tests and releases from the first commit.

This repository is a **GitHub template**. The product is called `Template` here (domain `example.com`) until
`scripts/init.sh` gives it its real name.

## Features

- Menu bar app skeleton in SwiftUI and Swift 6, with a sample Example screen in four states (loading, loaded, empty, failed).
- Logic in a local Swift package (`TemplateCore`), project generated by XcodeGen, tests written with Swift Testing.
- In-app updates with Sparkle 2, localization in nine languages, and design tokens with a token page and mockups.
- Release tooling: version bump, signing and notarization script, secret scan, and tests for all of them.
- Two starting points chosen at init time: an open-source (MIT) project or a closed-source product skeleton.

## Requirements

- macOS 26.0 or later.
- Xcode 27 (preferred; CI selects it when the runner has it, otherwise the newest installed Xcode).
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`) and Python 3.

## Quick start

1. On GitHub choose **Use this template** and create your repository.
2. Clone it and run `scripts/init.sh <Name> <domain>`:

   ```bash
   scripts/init.sh Acme acme.com                       # open-source project (MIT), the default
   scripts/init.sh Acme acme.com --license proprietary # closed-source product skeleton
   ```

3. Check the result:

   ```bash
   xcodebuild test -project Acme.xcodeproj -scheme Acme -destination 'platform=macOS' \
     -testLanguage en -testRegion US CODE_SIGNING_ALLOWED=NO
   xcrun swift-format lint --strict --recursive Acme AcmeCore AcmeTests
   ```

4. Generate the Sparkle key (`generate_keys --account <name>`), put the public key in `SPARKLE_PUBLIC_KEY` in
   `project.yml`, run `xcodegen generate`, and replace the Example screen with your first real screen.

Nothing is committed for you: review `git status` and commit the files you checked.

## Usage

### `scripts/init.sh` options

```text
scripts/init.sh <Name> <domain> [--license mit|proprietary] [--owner <github-user>] [--repo <name>] [--no-generate]
```

| Option | Meaning |
|---|---|
| `<Name>` | Product name in PascalCase (letters and digits, starts with a capital); becomes the module, target, scheme and visible name |
| `<domain>` | Product domain, lowercase; the bundle id becomes `<domain-reversed>.app` (`acme.com` gives `com.acme.app`), downloads `https://dl.<domain>`, support `support@<domain>` |
| `--license mit` (default) | Open-source project, see the table below |
| `--license proprietary` | Closed-source product skeleton, see the table below |
| `--owner <user>` | GitHub user or organization for `CODEOWNERS` and URLs; inferred from `git remote origin` when omitted, otherwise `CODEOWNERS` gets a `* @<owner>` placeholder to fill in |
| `--repo <name>` | Repository name (default: the lowercase product name) |
| `--no-generate` | Do not run `xcodegen` at the end |

### `mit` or `proprietary`

| | `--license mit` | `--license proprietary` |
|---|---|---|
| `LICENSE` | MIT | Terms of service, all rights reserved |
| `README.md` and `README.zh-CN.md` | Open-source README with an MIT badge and a CI badge | Product README with a proprietary badge, a pre-release status badge and sentence, no CI badge, no Website badge, download link or mailbox, and a documentation index |
| Shared files | `CONTRIBUTING.md`, `AGENTS.md`, `CLAUDE.md`, `CHANGELOG.md`, `CODEOWNERS`, `pr-title.yml`, Dependabot | The same, with closed-source wording |
| `ci.yml` | Builds and tests on every pull request | Cheap Linux checks always; the macOS job only for release candidates and manual runs |
| Release workflow | none | None until launch; `docs/launch.md` copies the self-contained `release.yml` (signing, notarization, upload) from `.template/launch/` |
| Extra documents | none | `docs/spec.md`, `legal.md`, `website.md`, `releasing.md`, `launch.md`, `roadmap.md`, `docs/security/`, `CHANGELOG.zh.md` and the website changelog tool |
| AI tooling | `AGENTS.md` | Also `.claude/` and `.codex/` |

The skeleton files live in `.template/oss/` and `.template/product/`; `init.sh` copies one of them over the tree,
renames `Template*` to `<Name>*`, rewrites names, bundle id, URLs and Sparkle settings (including both READMEs),
regenerates the Xcode project, and deletes `.template/`, itself and `scripts/test-init.sh`. The generated
`README.md` and `README.zh-CN.md` replace the ones you are reading. See [.template/README.md](.template/README.md).

### Generated project layout

| Path | Purpose |
|---|---|
| `project.yml`, `Config/` | XcodeGen definition, `Version.xcconfig`, Info.plist keys, `release.conf` (every product-specific release value) |
| `<Name>/` | App target: `App/` (entry point, language, links, updater), `UI/Example/` (the sample screen), `Resources/` |
| `<Name>Core/` | Local Swift package: `Domain/`, `Services/`, `Design/` (`DesignTokens`) |
| `<Name>Tests/` | Swift Testing: model, links, language, bundle and localization tests |
| `docs/`, `design/` | Design language, architecture decision records, token page and Example screen mockup |
| `scripts/` | `release.sh`, `release-credentials.sh`, `bump.sh`, `scan_secrets.py` and their tests |

## Development

```bash
xcodegen generate
xcrun swift-format lint --strict --recursive Template TemplateCore TemplateTests
xcodebuild test -project Template.xcodeproj -scheme Template -destination 'platform=macOS' \
  -testLanguage en -testRegion US CODE_SIGNING_ALLOWED=NO
scripts/test-release.sh
scripts/test-init.sh    # runs init.sh on throw-away copies for both licenses (--full also builds the proprietary copy)
```

`Template` and `example.com` are the placeholders `init.sh` replaces; do not write a real product name anywhere
in this repository.
